# 近期活動總覽規格

**狀態：** cms-integrated
**路由：** `/events`  
**頁面模式：** Persuade；協助訪客比較近期可參與的短期活動並採取下一步  
**設計依據：** [`course.md`](course.md)、[`DESIGN.md`](../../DESIGN.md)、目前 `CourseOverview.vue` 的 30%／70% 雙域節奏，以及已核准的 [「月份長譜」首屏稿](../../.impeccable/mocks/decision/events-monthly-score.webp)；活動頁延續字體尺度、左右分區、色系與 1023px 響應式斷點，但不複製課程分類錨點或光片互動

## 目標與受眾

主要受眾是已對身心學習有興趣、希望先以短期形式了解內容或參與方式的訪客。頁面讓訪客先看見仍可參與的近期活動，理解日期、活動形式、時間、地點／線上方式與報名狀態，再決定是否查看關聯課程或前往報名；也可瀏覽過去活動，理解曾經舉辦的主題，但不把歷史紀錄誤認為仍可報名。

成功標準是訪客在不開啟活動詳情頁的情況下，仍能分辨「活動是什麼、何時舉行、如何參與、目前能否報名」。正式報名連結尚未確認，因此第一版必須能在沒有報名網址時完整呈現資訊。

## 範圍與非目標

第一版包含共用 `SiteHeader`、頁面識別區、近期活動集合、過去活動集合、活動狀態、選填的關聯課程入口，以及共用 `SiteFooter`。活動類型至少能涵蓋一日工作坊、兩日工作坊與課程說明會；類型名稱由編輯者維護，不在前端寫死。近期集合以尚未結束的已發布活動為主，過去集合只顯示已結束且允許公開留存的活動。

第一版不包含站內付款、會員、名額即時庫存、候補名單、行事曆同步、站內活動詳情頁、搜尋或篩選。近期與過去集合各自提供 URL 可還原的分頁，避免資料長期累積造成頁面過長；不實作無限捲動。也不新增未經確認的費用、師資、成效、見證或活動內容。首頁活動區未納入本階段實作，但日後應共用相同活動文件與排序規則，不維護第二份活動資料。

## 已確認事實、示範內容與工作假設

- 已確認：公開路由為 `/events`；頁面以近期短期活動為主，也可呈現過去曾舉辦的活動。
- 已確認：全站導覽已將「近期活動」連到 `/events`；目前該路由已有 fixture 驅動的前端原型，尚未接正式 CMS 資料。
- 已確認：視覺需與 `/course` 一致，包含繁中襯線標題、東亞無襯線內文、暖紙／淺砂／深赭色域、桌面左右區塊與手機單欄節奏；左側不要求使用錨點，右側可為活動資訊設計不同構圖。
- 已確認：採用「月份長譜」方向；月份作為段落分隔，每筆活動維持緊湊橫列，日期、內容、狀態與行動有穩定欄位，圖片只作選填增強。
- 已確認：報名開放且具有有效網址時，「前往報名」是活動的主要行動；到達開課時間後前台自動顯示「報名已截止」並移除報名行動。
- 已確認：近期與過去活動各自分頁，每頁 8 筆，避免任何一個集合無限拉長頁面。
- 示範內容：`HomeEvents.vue` 的活動名稱、日期、類型、時間及介紹文字皆是 fixture，不得直接發布或據此推論正式活動。
- 工作假設：活動是獨立內容文件，可選擇關聯一門既有課程；課程說明會或不屬於單一課程的活動可以不建立關聯。此假設需在 CMS 階段前確認。
- 工作假設：時間判定使用 `Asia/Taipei`；有明確結束時間時以結束時間分類，只有日期時以該日 23:59:59 分類。取消的活動不進入過去活動成果集合。

## 資訊架構與顯示規則

1. `SiteHeader` 從載入起顯示，並正確標示 `/events` 為目前頁面。
2. 桌面首屏以約 30%／70% 左右雙域開始：左側建立頁面名稱、短引導，以及「近期活動／過去活動」雙檢視切換；右側只呈現目前選取的活動集合，不加入首頁式 banner 或玫瑰地圖。
3. 左側切換使用具 URL 的原生連結語意，不是內容篩選、頁內錨點或只能靠 JavaScript 運作的 tab。選取項以文字粗細、暖黃色位置線及 `aria-current="page"` 共同標示，並顯示該集合總筆數；空集合仍保留切換入口，讓使用者可回到另一集合。
4. 近期活動依 `startAt` 由近到遠排列；同一開始時間以 `order`、再以穩定文件 ID 排序。新發布或日期更新的活動會依日期自動插入正確位置，不依建立時間或人工拖曳決定前後。
5. 當 `now >= startAt` 時，有效前台狀態一律切換為「報名已截止」並移除報名連結，不等待編輯者更新 CMS；活動在 `now < endAt` 期間仍留在近期集合，讓進行中的活動不會突然消失。
6. 當 `now >= endAt` 時，`archiveVisible` 為 `true` 的活動移入過去集合，依 `endAt` 由新到舊排列；`archiveVisible` 為 `false` 時不公開留存。此轉換由請求當下時間推導，不回寫 CMS。
7. 目前檢視每頁 8 筆，URL 使用 `view=upcoming|past` 與 `page=<正整數>`；預設為 `view=upcoming&page=1`。切換檢視時從目標集合第 1 頁開始，瀏覽器上一頁可回到切換前的檢視與頁碼；換頁後將焦點移至集合標題。不存在、非正整數或超出範圍的頁碼正規化至有效頁，不顯示空白頁。
8. `cancelled` 不出現在公開集合；若未來有公告取消資訊的需求，另行定義，不以本頁一般活動列承載。
9. 每筆活動最多只有一個主要行動。有效狀態為 `open`、尚未到 `startAt` 且有核准 HTTPS 網址時顯示「前往報名」；沒有報名入口但有關聯且已公開的課程時顯示「了解課程」；其餘狀態只提供資訊，不產生失效連結。

### 時間與有效狀態推導

依 `Asia/Taipei` 的請求當下時間套用下列優先順序：

1. `cancelled`、未公開或日期無效：不顯示。
2. `now >= endAt`：若允許留存則進入過去活動；不顯示報名行動。
3. `startAt <= now < endAt`：留在近期活動，有效狀態固定為「報名已截止」。
4. `now < startAt`：沿用 CMS 的 `scheduled`、`open`、`full` 或 `closed`；只有有效狀態為 `open` 且網址合格時顯示「前往報名」。

排序與分頁都在完成過濾及有效狀態推導後進行。日期接近不會觸發排程工作或修改文件；下一次 SSR、API 請求或前端跨越邊界時間時重新計算即可。前端在頁面保持開啟時需安排最近一個 `startAt`／`endAt` 邊界的單次更新，避免使用者必須重新整理才看到截止或移入過去。

## 狀態與行為

- **一般：** 右側只顯示左側目前選取的有效集合；預設為近期活動，過去活動透過獨立檢視切換。
- **Loading：** 保留左右雙域與文字節奏，使用無虛構文字的低對比骨架；容器設定 `aria-busy="true"`，不朗讀每一條骨架。
- **近期空、過去有資料：** 首先顯示 `emptyMessage`，其後仍可瀏覽過去活動；不得把歷史項目提升成近期內容。
- **完全空：** 保留頁面身份與共用導覽，右側顯示單一明確空狀態；不顯示 0 筆計數、空清單或失效操作。
- **Error：** 保留 Header、頁面身份與 Footer；右側說明暫時無法載入並提供「重新載入」按鈕。不得用 fixture 假裝為正式資料。
- **缺少選填內容：** 無圖時使用品牌平面表面而非破圖或虛構照片；無場地、補充或關聯課程時直接省略，不留下空標籤。
- **長內容／大量內容：** 40 字標題、100 字摘要、80 字場地與 12 筆近期活動均不得造成截斷、重疊或水平捲動。
- **檢視切換：** 右側只顯示目前選取集合；切換時更新 URL、將頁碼重設為 1，並把焦點移至新的集合標題。若載入可由同一份前端資料立即完成，不顯示不必要的 loading；需重新請求時保留左欄與既有內容，成功後再替換。
- **分頁：** 只有一頁時不顯示控制項；五頁以內顯示所有可直接操作的頁碼，超過五頁時保留首頁、尾頁與目前頁附近的頁碼，其餘以省略號縮略，切頁後同步更新；前後另提供上一頁與下一頁。不可操作的上一頁／下一頁使用原生 disabled 語意；切頁保留 Header 與目前檢視，載入失敗時停留原頁並提供重試。分頁上方不加分隔線，也不額外顯示「第幾頁、共幾筆」摘要。
- **互動回饋：** 每筆活動的內容區連到 `/events/{slug}` 詳情頁，hover 與 `focus-visible` 提供等價提示；「前往報名」維持獨立的外部 HTTPS 連結，以新分頁開啟，並在無障礙名稱中說明且使用安全的 `rel` 屬性。活動內容連結與報名連結不得互相巢狀。

## 視覺與響應式約束

- `>= 1024px` 延續 course 的約 30%／70% 左右分區與固定 Header 下方起始位置。左側可 sticky，但內容超高時必須能獨立捲動；雙檢視切換排列在導讀下方，每項至少 44px 高且整列可操作。右側以活動的日期節奏、時間跨度與狀態建立構圖，不複製課程光片的橫向擴張。
- 右側採「月份長譜」：月份標題是連續列表的節拍分隔，每筆活動為短橫列；日期在窄欄、內容在主欄、狀態與主要行動靠尾端，單筆不因有圖或長摘要膨脹成大型卡片。集合標題下方不加分隔線；每個月份內的活動列保留分隔，但該月份最後一筆活動不顯示下底線。分頁置於各集合末端，不使用浮動或固定頁碼列。
- `<= 1023px` 依文件順序改成單欄，頁面識別先於活動集合。不得為維持桌面構圖而建立水平滑動列表。
- 主要內容左右留白沿用 `clamp(28px, 6vw, 116px)` 的全站尺度；標題、內文與 label 分別沿用 `DESIGN.md` 的 display、body、label 字體角色。
- 基底只使用既有 paper、sand、ink、muted、clay、saffron、film／night 與 warm-white token。柿橘保留給真正可執行的主要行動；不新增圓角卡片、浮動陰影、柔焦療癒圖或漂浮漸層。
- 動態只能協助理解目前聚焦項目或近期／過去的轉換，不能延遲閱讀；`prefers-reduced-motion` 下移除位移、展開及平滑捲動。
- 至少驗證 1440、1023、768、390、320px，以及 200% 文字放大／等效窄視窗；所有互動目標至少 44 × 44px。

## 語意、鍵盤與替代文字

`main` 只有一個 `h1`；近期與過去集合各為具 `h2` 的 `section`，活動使用有序或無序清單，活動名稱使用下一層標題。日期使用 `<time datetime>`，視覺拆分的月份與日不得造成螢幕閱讀器重複朗讀。主要行動依目的使用 `<a>`，重新載入使用 `<button>`；DOM、鍵盤與視覺順序一致，不把整張卡和卡內次要連結做成巢狀互動。

有內容意義的圖片 alt 描述畫面提供的資訊，不重複活動名稱；純裝飾圖片使用空 alt。狀態不能只靠顏色表達，焦點在所有既有表面上皆需清楚可見。Loading、Error 與資料更新使用合宜的 live region，避免整份列表更新時重複朗讀。

## 驗收條件

1. `/events` 使用共用 Header／Footer，Header 正確標示目前頁，頁面只有一個 `h1`。
2. 桌面呈現約 30%／70% 雙域，1023px 以下改為單欄；字體尺度、色系與間距明顯延續 `/course`，但活動內容不是課程光片的複製版。
3. 近期活動依開始時間升冪、過去活動依結束時間降冪；邊界時間以 `Asia/Taipei` 正確分類，跨日活動不會提早進入過去集合。
4. `full`、`closed` 且尚未結束的活動仍留在近期並以文字顯示狀態；`cancelled`、未公開及無效日期資料不顯示。
5. 完全空、只有過去、Loading、Error、缺圖、無報名連結、長內容及 12 筆近期活動都有清楚且可操作的呈現，不以首頁 fixture 補位。
6. `open` 且具有核准 HTTPS 網址時才顯示外部報名行動；無報名網址時不產生空連結，具公開關聯課程時可改顯示課程入口。
7. 同日、跨日、跨月與跨年活動皆由 `startAt`／`endAt` 正確格式化，不在 CMS 重複保存月份、日期或星期文案。
8. 320–1440px 無水平溢位；200% 文字放大時內容與控制項不被裁切，觸控目標至少 44px，鍵盤焦點可見。
9. 標題層級、list 與 `time` 語意正確；圖片替代文字、狀態非純色彩表達，以及 reduced-motion 行為皆通過檢查。
10. 首頁未在本階段改動；後續資料化時首頁最多三筆活動必須查詢同一活動來源，不建立重複文件。
11. `now` 跨過 `startAt` 時活動不需 CMS 更新即顯示「報名已截止」並移除報名連結；跨過 `endAt` 時依 `archiveVisible` 自動移入過去集合或隱藏。
