# 個案諮詢總覽規格

**狀態：** verified

**路由：** `/session`

**頁面模式：** Browse；協助訪客按所在地區與服務項目縮小選擇，再前往合適的執行師詳情

**設計依據：** [`course.md`](course.md)、[`events.md`](events.md)、[`DESIGN.md`](../../DESIGN.md)，以及使用者提供的舊站截圖；延續 `/course`、`/events` 的桌面約 30%／70% 雙域、左側固定／sticky 與右側內容節奏，舊站只作欄位參考，不沿用版面或內容

## 目標與受眾

主要受眾是已有個案諮詢需求，但尚不確定適合哪一位執行師或哪一種服務項目的訪客。頁面先用服務地區與服務項目標籤縮小範圍，再讓訪客比較姓名、服務項目與服務地區，進入個別詳情了解經歷、服務說明及聯絡／預約方式。

成功標準是訪客能辨認目前套用的條件、找到符合條件的執行師，並理解下一步是查看詳情；沒有符合結果時，也能清除篩選而不會進入空白或失效頁面。公開介面統一使用「執行師」，「療癒師」只作使用者搜尋情境的同義描述，最終用語仍可由內容負責人確認。

## 範圍與非目標

第一版包含共用 `SiteHeader`／`SiteFooter`、頁面識別與導讀、地區及服務項目兩組標籤、清除篩選、符合條件的執行師列表、URL 可還原的分頁，以及前往 `/session/[slug]` 的詳情入口。桌面左側負責頁面識別與篩選，右側顯示目前結果；1023px 以下依文件順序改為單欄。

第一版不包含關鍵字搜尋、距離定位、地圖、收藏、比較表、即時可約時段、站內預約、付款、會員功能、評分、療效保證或個人化推薦。執行師詳情頁的完整內容與聯絡／預約流程屬後續規格；本頁只保留詳情路徑契約，不自行推定詳情內容。

## 已確認事實、示範內容與工作假設

- 已確認：公開路由為 `/session`，目的是協助訪客尋找執行師／療癒師。
- 已確認：桌面延續 event、course 的左側固定、右側內容方向；左側提供標籤篩選，右側提供執行師列表及頁碼。
- 已確認：地區至少需要涵蓋「北部、中部、南部」；初始服務項目以「身心再平衡按摩」、「生物動能頭薦骨」、「日式臉部按摩」、「人類圖」為主。服務項目是可新增的 taxonomy，不是四個寫死欄位；每位執行師可關聯多個服務項目。
- 已確認：分頁的視覺與互動可沿用 `/events` 已使用的頁碼模式，不另造一套不一致的控制項。
- 參考內容：舊站可辨認姓名、選填英文名、服務項目及「more」詳情入口；截圖中的人物姓名、照片、排序及療法組合不是已核准正式內容。
- 工作假設：同一篩選群組內採 OR（例如北部或中部），不同群組之間採 AND（例如北部，且提供生物動能頭薦骨）；此規則能支援多據點、多專長的執行師，設計階段可直接據此呈現。
- 工作假設：每頁 8 筆，先依人工 `order`、再依中文姓名及穩定 ID 排序；正式資料量確認後可在不改資訊架構的前提下調整單頁筆數。

## 資訊架構與顯示規則

1. `SiteHeader` 從載入起顯示，並將「個案諮詢」標示為目前頁面。
2. 桌面主內容以約 30%／70% 雙域呈現。左側依序包含唯一 `h1`、短導讀、地區標籤、服務項目標籤及清除操作；右側包含結果標題、選取條件摘要、執行師清單與分頁。
3. 初次進入時不預選標籤，顯示全部已公開執行師。標籤為可切換的原生按鈕；同一執行師可關聯多個地區及多個服務項目。
4. URL 使用重複 query 保存狀態，例如 `/session?region=north&method=biodynamic-craniosacral&page=2`。標籤使用穩定 key，不把中文顯示名稱直接當資料關聯；重新整理、分享網址及瀏覽器上一頁／下一頁都需還原篩選與頁碼。
5. 新增或移除任何標籤時回到第 1 頁，並將焦點移至更新後的結果標題。未知 key、非正整數或超出範圍的頁碼須正規化，不顯示空白頁。
6. 右側只呈現完成篩選後的結果。若服務地區與服務項目都有選取，執行師必須至少符合一個所選地區及一個所選服務項目；先篩選、再排序、最後分頁。
7. 每筆列表至少顯示中文姓名、選填英文名、公開地區與服務項目，整個主要內容區連到 `/session/[slug]`。第一版不在列表直接放預約按鈕，避免訪客未理解服務內容即離站。

### 執行師列表內容

| 欄位 | 語意與型別 | 必填與合理範圍 | 編輯責任／預定來源 |
| --- | --- | --- | --- |
| `name` | 執行師公開中文姓名 | 必填，2–20 字 | 執行師內容編輯者／Sanity practitioner document |
| `englishName` | 英文名或公開稱呼 | 選填，2–40 個拉丁字元 | 執行師內容編輯者／Sanity |
| `slug` | 詳情頁穩定識別碼 | 必填且唯一，1–60 個小寫英數與連字號 | 執行師內容編輯者／Sanity |
| `regions` | 服務地區 references | 必填，1–5 項且不重複 | 執行師內容編輯者／Sanity taxonomy |
| `methods` | 可提供的服務項目 references；一位執行師可複選多項 | 必填，至少 1 項且不重複；選項來自可擴充 taxonomy，不以自由文字重複建立 | 執行師內容編輯者／Sanity taxonomy |
| `summary` | 協助理解服務取向的短摘要 | 選填，20–100 字；第一版列表可依設計決定是否顯示 | 執行師內容編輯者／Sanity |
| `order` | 列表人工優先順序 | 必填，正整數；允許同值並以姓名、ID 穩定排序 | 執行師內容編輯者／Sanity |
| `isPublished` | 是否可出現在公開總覽及詳情 | 必填，boolean | 執行師內容編輯者／Sanity |

正式 taxonomy 由內容負責人維護，前端不得把「北部」或四種初始服務項目寫死成欄位。新增技能時先建立或選用 taxonomy 項目，再由執行師文件複選 references，避免同義字與錯字形成重複篩選；前端依發布內容與 `order` 自動增加選項。地區描述公開服務範圍，不推論或顯示精確地址；若日後需要線上服務，應新增經確認的 taxonomy 項目，不把它混成實體地區。列表與詳情共用同一執行師文件及公開開關，避免兩份姓名或專長資料不同步。總覽頁不讀取或顯示執行師照片；`pageTitle` 以純文字插值輸出，使用 `white-space: pre-line` 呈現換行，不使用 `v-html`。

## 狀態與行為

- **一般：** 顯示全部公開執行師；選取標籤後即更新條件摘要、結果數及列表，不需額外送出按鈕。
- **Loading：** 保留雙域、篩選標題與列表節奏，右側使用不含虛構姓名的低對比骨架；結果容器設定 `aria-busy="true"`。
- **完全空：** 保留頁面身份與 Footer，右側顯示 `emptyMessage`；不顯示無意義的篩選、0 筆摘要或分頁。
- **無符合結果：** 保留目前選取標籤，顯示 `noMatchesMessage` 與「清除全部篩選」按鈕；不可偷偷放寬條件或改顯示不符合的執行師。
- **Error：** 保留 Header、頁面身份與 Footer，右側顯示暫時無法載入及重新載入按鈕；不得以 fixture 假裝正式資料。
- **缺少選填內容：** 無英文名或摘要時直接省略，不留下空標籤或虛構替代內容；姓名、地區、服務項目或 slug 無效的項目不得公開渲染。
- **長內容／大量內容：** 20 字姓名、40 字英文名、12 個服務項目與至少 48 位執行師不得造成截斷、重疊或水平捲動；標籤文字自然換行。
- **分頁：** 沿用 `/events` 的頁碼規則與視覺語言。只有一頁時不顯示；五頁以內列出全部頁碼，超過五頁時保留首頁、尾頁及目前頁附近頁碼，其餘用省略號；另有上一頁／下一頁，邊界使用原生 disabled 語意。換頁保留篩選，更新 URL 並把焦點移至結果標題。
- **互動回饋：** 選取標籤、目前頁與目前結果不能只靠顏色表達；hover、active 與 `focus-visible` 必須提供等價且清楚的狀態。資料更新時只朗讀簡短結果摘要，不逐筆重讀整份清單。

## 視覺、響應式與無障礙約束

- `>= 1024px` 延續 course、events 的約 30%／70% 左右分區。左側可 sticky，但標籤超過視窗高度時必須能正常捲動，不遮住共用 Header；右側以細線分隔的執行師列表建立節奏，不直接複製舊站的巨大裝飾照片或通用卡片牆。
- `<= 1023px` 依 DOM 順序改為單欄，頁面識別與篩選先於結果；篩選不可只收進預設關閉且無名稱的抽屜。若使用可展開區塊，控制項需揭示展開狀態並可由鍵盤操作。
- 主要留白、字體角色與 paper、sand、ink、muted、clay、saffron、film／night、warm-white token 沿用 `DESIGN.md`。不新增圓角膠囊海、陰影卡片、柔焦人物背景或漂浮漸層；標籤即使採緊湊外觀，點擊目標仍至少 44 × 44px。
- `main` 只有一個 `h1`；篩選使用具名稱的 `form` 或 `section`，兩組條件使用 `fieldset`／`legend` 或等價語意；執行師使用 list，姓名使用一致的後續標題層級。詳情入口為原生 `<a>`，篩選與清除為 `<button>`。
- 目前篩選狀態需以 `aria-pressed` 或等價原生狀態呈現；結果更新與焦點管理不可造成鍵盤使用者失去位置。總覽不載入人物圖片，僅有的裝飾圖形需從輔助技術隱藏。
- 名錄列的地區文字在桌機與手機皆為 14px；服務項目在桌機為 16px，620px 以下為 14px，以兼顧桌機掃讀與手機換行密度。
- 桌機的 `session-directory__aside` 不顯示右側邊線，sand 與 paper 直接以背景色面區隔；1023px 以下仍保留篩選區底部分隔線，維持單欄內容層次。
- 尊重 `prefers-reduced-motion`；移除列表位移、平滑捲動及標籤動畫後，篩選、分頁與焦點仍完整可用。至少驗證 1440、1023、768、390、320px，以及 200% 文字放大／等效窄視窗。

## 驗收條件

1. `/session` 使用共用 Header／Footer，Header 正確標示目前頁，且 `main` 只有一個 `h1`。
2. 桌面呈現約 30%／70% 雙域，左側包含地區與服務項目篩選，右側包含執行師列表；1023px 以下依語意順序轉為單欄且無水平溢位。
3. 初始狀態顯示全部已公開且契約有效的執行師；未公開或缺少姓名、slug、地區或服務項目的資料不出現在列表。
4. 同組多選採 OR、跨組採 AND；篩選在分頁前完成，結果數、列表與頁數同步更新，不出現不符合條件的項目。
5. 篩選 key 與 `page` 寫入 URL；分享、重新整理及瀏覽器上一頁／下一頁可還原狀態，未知 key 與無效／超界頁碼會正規化。
6. 變更篩選時回到第 1 頁；換頁保留所有條件，並把焦點移至結果標題。每頁 8 筆，只有一頁時不顯示分頁。
7. 每筆列表顯示姓名、地區與服務項目，不渲染執行師照片或照片空槽；英文名、摘要缺少時版面仍成立，主要連結正確指向 `/session/[slug]`。
8. Loading、完全空、無符合結果、Error、缺少選填內容、長標籤與至少 48 位執行師都有明確且可操作的呈現，不以舊站或 fixture 內容補位。
9. 所有篩選、清除、詳情與分頁操作可由鍵盤完成；選取狀態與目前頁不只依賴顏色，焦點可見，互動目標至少 44 × 44px。
10. 320–1440px 及 200% 文字放大不裁切姓名、標籤或頁碼；reduced-motion 下資訊、焦點移動與 URL 行為不變。
11. `pageTitle` 可由後台輸入最多一個純文字換行，前台依輸入斷行且不執行 HTML；正式頁面不發布舊站截圖中的姓名、排序或療法組合，除非內容負責人另行核准並輸入 CMS。

## 依賴、待決事項與下一階段

- 內容負責人需確認地區 taxonomy、四種初始服務項目的正式命名，以及正式執行師名單、公開姓名、服務範圍、服務項目、排序及選填摘要；後續可新增技能 taxonomy，不需修改前端欄位。

- A「經緯名錄」已完成桌機、手機、Sanity 整合與 production 內容流驗收；遠端 schema 已部署，隔離測試內容已清除。總覽不需要人物照片欄位或圖片資產，正式上線仍需內容負責人建立並發布總覽文案、taxonomy 與執行師資料。
