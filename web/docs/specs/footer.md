# Footer 功能規格

**狀態：** draft

**範圍：** 全站 Footer 第一版

**依據：** `PRODUCT.md`、`DESIGN.md`、`docs/specs/header.md`、`docs/design/footer-concepts-v3-award.html` 的 L「靜默座標」及現有 `SiteFooter.vue`

## 目標與受眾

讓完成頁面閱讀、準備採取下一步的訪客，在頁尾辨識品牌、取得聯絡方式，並前往主要站內單元。第一版沿用已選定的 L「靜默座標」方向，以暖砂底面、品牌訊息與低干擾的感知路徑收束內容；動態只提供氛圍，不承載資訊或操作狀態。

## 範圍與非目標

第一版包含品牌識別、品牌主張、實體地址、電話、Email、社群入口、站內導覽、版權資訊、裝飾路徑動畫及無障礙替代行為。先整合至現有 `/` 與 `/course`，後續新增公開頁面時共用同一元件與內容來源。

本階段不建立或修改 UI、Sanity schema 或正式資料；不包含地圖、路線規劃、聯絡表單、電子報、會員、報名與付款流程，也不把舊站內容或 prototype 的 `#` 連結視為可發布資料。

## 內容契約

| 欄位 | 語意與型別 | 必填／長度與數量 | 編輯責任 | 預定資料來源 |
| --- | --- | --- | --- | --- |
| `brandName` | 品牌可讀名稱；字串 | 必填；2–20 個中文字 | 品牌負責人 | 全站設定；暫定「普那生活空間」待確認 |
| `brandLogo` | 品牌標誌；圖片資產 | 必填；1 張，須有固有尺寸 | 品牌／前端 | 現有 `public/assets/logo-main.png`，發布前確認版本 |
| `closingStatement` | 收束頁面的中文品牌句；純文字 | 選填；10–28 個中文字 | 品牌／內容負責人 | 全站設定；prototype 文案僅為示範 |
| `brandStatement` | 品牌英文主張；純文字及語言標記 | 必填；20–80 個英文字元 | 品牌／內容負責人 | 全站設定；prototype 文案待確認 |
| `address` | 可公開的實體地址；純文字 | 選填；10–60 個中文字 | 內容負責人 | 預定 Sanity 全站設定；舊站截圖內容待確認 |
| `phone.display` | 使用者看見的電話；字串 | 選填；8–25 字元 | 內容負責人 | 預定 Sanity 全站設定 |
| `phone.href` | 國際格式 `tel:` URI；字串 | `phone.display` 存在時必填；1 個 | 內容／前端 | 預定 Sanity 全站設定 |
| `email` | 可公開 Email；字串 | 選填；最長 254 字元 | 內容負責人 | 預定 Sanity 全站設定 |
| `socialLinks[]` | 社群名稱與 HTTPS 網址；物件陣列 | 選填；0–4 筆，名稱 2–20 字元 | 內容負責人 | 預定 Sanity 全站設定；Facebook、LINE 網址未提供 |
| `navigationItems[]` | 站內目的地名稱與路徑；物件陣列 | 必填；固定 5 筆，名稱 2–8 個中文字 | 產品／前端 | 與 `app/constants/siteNavigation.ts` 共用，不在 Footer 重複維護 |
| `copyrightText` | 著作權聲明；純文字 | 必填；10–100 字元 | 品牌／內容負責人 | 全站設定；年份呈現方式待確認 |

「全站設定」的正式儲存位置尚未建立。依 `PRODUCT.md` 的內容管理原則，預定由 Sanity 單例文件管理可編輯內容；schema 名稱、欄位驗證與查詢策略留待資料整合階段確認。導覽屬產品資訊架構，第一版仍由前端共用常數管理。Footer 固定依序使用「近期活動」`/events`、「課程探索」`/course`、「個案諮詢」`/session`、「文章分享」`/articles`、「關於我們」`/about`，與 Header 完全一致。所有 prototype 聯絡資料皆為示範內容，核准前不得發布。

## 狀態與行為

- 一般狀態顯示品牌、可用聯絡資訊、站內導覽與版權；電話開啟系統撥號、Email 開啟郵件程式、社群連結前往已核准的 HTTPS 網址，站內導覽使用 Nuxt 路由。
- 第一版應以伺服器端取得或建置期可用的內容渲染，不顯示獨立 loading 骨架。若未來改為用戶端取得資料，須另定避免版面位移與重複朗讀的 loading 契約。
- 全站設定缺失或讀取失敗時，仍保留品牌識別、共用站內導覽及版權區，不顯示未確認值、`#`、空連結或「待確認」文字；錯誤可記錄於伺服器端，但不得把敏感內容寫入瀏覽器紀錄。
- 地址、電話、Email、中文收束句及社群入口均可獨立省略；缺少選填欄位時移除整個對應元素與間距。必要品牌或導覽設定缺失屬發布阻擋，不得以 prototype 值靜默補位。
- 長地址、Email、品牌句與導覽名稱允許換行，不截斷核心資訊，不造成水平捲動；Email 與長網址須能安全斷行。
- 三條白色路徑為靜態裝飾；兩組稀疏白點可用不同速度與相位沿路徑流動。Footer 未進入視窗、文件不可見或元件卸載時停止動畫；重新可見時可恢復。Hover 或鍵盤焦點可提高光點可見度，但不可成為理解連結狀態的唯一線索。
- `prefers-reduced-motion: reduce` 時不顯示移動點群，只保留靜態路徑；內容與操作能力不得減少。

## 響應式與無障礙

桌面延續 L 案的偏軸雙欄資訊結構；`<= 900px` 改為單欄並隱藏僅供桌面構圖使用的中文收束句，改由行動版品牌標誌開始閱讀；`<= 560px` 收斂內距並確保從 320px 起無水平溢位。視覺排列改變不得改變 DOM 的品牌、主張、聯絡、導覽、版權閱讀順序。

根元素使用 `footer`；聯絡資料使用 `address`，頁尾導覽使用有「頁尾導覽」名稱的 `nav`。品牌標誌若同時提供可讀品牌名稱，可使用空 `alt`；若標誌是唯一品牌名稱，替代文字使用核准的 `brandName`。英文主張標記 `lang="en"`。裝飾 SVG 使用 `aria-hidden="true"` 且不可聚焦。所有連結保留可見焦點，鍵盤順序與 DOM 一致，觸控目標至少 44 × 44px；純裝飾箭頭不提供替代文字。

## 驗收條件

1. `/` 與 `/course` 顯示同一個共用 Footer，且品牌、聯絡、導覽與版權資料不由頁面各自複製。
2. 核准資料存在時，電話產生有效 `tel:` URI、Email 產生有效 `mailto:` URI、社群使用 HTTPS 網址；頁面不得出現 `href="#"` 或「待確認」內容。
3. 每個頁尾導覽項目名稱、順序與目的地皆取自同一份共用設定；點選後 URL 與目標頁正確，目的頁不存在時不得通過驗收。
4. 任一選填聯絡欄位缺少、全部選填聯絡欄位缺少、內容讀取失敗或文字達建議上限時，Footer 仍保留必要資訊，沒有空控制項、重疊或水平捲動。
5. 320、560、900、1024 與 1440px 寬度下，內容順序正確、文字可讀、連結可操作，且行動版不顯示桌面專用收束句。
6. 僅使用鍵盤可依序操作所有連結，焦點清楚可見；語意檢查可辨識 `footer`、具名稱的 `nav`、`address` 與品牌替代文字，裝飾 SVG 不進入無障礙樹。
7. Footer 進入／離開視窗、頁籤顯示／隱藏及元件卸載時，動畫啟停與監聽器清理可由測試觀察；reduced motion 下移動點群不存在但三條靜態路徑保留。
8. 相關 Vitest 行為測試、`npm run typecheck -w web` 與 `npm run build -w web` 通過，並完成 320px 起的桌面／行動視覺驗收後，才能把 production 整合標示為完成。

## 待決事項、依賴與下一階段輸入

- 內容負責人須核准品牌中英文主張、地址、電話、Email、社群名稱與實際網址、版權文字及年份策略；這些項目阻擋正式發布。
- Footer 已確認完整沿用 Header 的 5 項導覽。L prototype 暫放 4 項且把 `/course` 標為「創藝身心路徑」，屬尚未同步的舊稿差異；production 實作必須補上「文章分享」並使用已確認名稱。
- `/events`、`/session`、`/articles` 與 `/about` 目前是否已具備可到達頁面須在整合前確認；失效目的地不得上線。
- 資料整合階段需決定 Sanity 全站設定單例、缺值政策與發布驗證；視覺開發階段需提供 production SVG 路徑、動畫參數及斷點稿。
- 下一階段才修改 `SiteFooter.vue`、跨頁整合與測試。現有 prototype 的桌面、手機及 reduced-motion 截圖只證明概念稿已檢視，不代表 production 已完成或正式內容已核准。
