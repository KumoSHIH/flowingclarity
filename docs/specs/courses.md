# 課程總覽頁規格

## 狀態與依據

狀態：`draft`。公開路由為 `/courses`；課程詳情第一版暫用 `/courses/[slug]`，日後會移除 `/courses` 前綴，因此所有詳情連結必須由單一路由產生器建立，不可在元件或 CMS 內儲存完整站內路徑。本規格依據 [PRODUCT.md](../../web/PRODUCT.md)；[課程頁概念稿](../design/course-page-concepts.html) 僅供後續視覺探索，不代表核准內容。

## 目標與受眾

服務正在評估身心相關課程的使用者。頁面須讓使用者理解四個學習方向、比較各方向的課程與授課形式，並進入個別課程頁取得完整內容及後續報名入口。

## 範圍與非目標

第一版包含頁面導言、四個固定分類、已發布課程清單、授課形式及詳情連結。已確認分類與課程為：愛身體（頭薦骨、再平衡按摩、日式臉部按摩）、撫慰心（童年依附創傷療癒）、究生命（人類圖）、展現美（曼陀羅靜心彩繪）；授課形式依 `PRODUCT.md`。

第一版不包含站內報名、付款、會員、搜尋、篩選、排序控制、費用、師資、成效宣稱或學員見證。課程日期會納入共用資料模型，供總覽、首頁與詳情頁使用；總覽是否顯示完整日期由後續設計決定。首頁示範文案、舊站圖片及概念稿中的額外課程不得視為正式資料。

## 內容契約

正式資料預定由 Sanity 管理；編輯責任為網站內容編輯者，實際負責人待指派。

| --- | --- | --- | --- |
| `pageTitle` | 頁面唯一主標題，string | 必填，4–20 字，1 筆 | 課程總覽單例 |

### 梯次與多階段日期

`course` 保存不隨開班改變的介紹；`run` 代表一次可報名的完整梯次；`stage` 代表該梯次的學習階段；`dateRange` 表示一段連續上課日。同一階段跨兩週上課時建立兩個 date range，不把 `2026/01/21~25` 存成不可運算的文字。顯示格式由前端依 `zh-TW` 產生，CMS 只儲存 ISO 日期。

以下僅為欄位結構示例，不是正式課程資料：

```yaml
stages:
  - title: 第一階
    order: 1
    dateRanges:
      - { startDate: 2026-01-21, endDate: 2026-01-25 }
      - { startDate: 2026-01-28, endDate: 2026-02-01 }
  - title: 第二階
    order: 2
    dateRanges:
      - { startDate: 2026-06-19, endDate: 2026-06-23 }
      - { startDate: 2026-06-26, endDate: 2026-06-30 }
  - title: 第三階
    order: 3
    dateRanges:
      - { startDate: 2027-01-16, endDate: 2027-01-20 }
      - { startDate: 2027-01-23, endDate: 2027-01-27 }
```

系統以所有 `dateRange.startDate` 的最早值推導 `run.firstStartDate`，以所有 `endDate` 的最晚值推導 `run.lastEndDate`；兩者不由編輯者重複輸入。日期區間不得互相重疊，並須依時間遞增。如果一次報名涵蓋三階，使用一個 run；如果每階可獨立報名，每階必須是獨立 run，不可只當作同一 run 的 stage。

## 狀態與行為

- 一般：依 `category.order` 分組，再依 `course.order` 顯示；每門課的整個標題連結或明確的「查看課程」連結導向暫定詳情路由。
- Loading：保留主標題與分類結構，顯示非閃爍的載入提示；不得呈現可點擊的假課程。
- Empty：完全無已發布課程時顯示可理解的空狀態，不顯示虛構內容；單一分類為空時保留分類說明並標示「課程準備中」。
- Error：顯示讀取失敗訊息與重試操作；若使用快取內容，須避免把過期內容標為最新。
- 缺少選填內容：無圖片時使用不帶替代文字的品牌裝飾面，不保留破圖空間；不得因此隱藏課程。
- 長內容：標題、摘要與分類文字自然換行，不裁切、不省略關鍵資訊，也不得造成水平捲動。
- 互動：連結 hover、focus 與啟用回饋需清楚；減少動態偏好下停用非必要位移與平滑捲動。

## 響應式與可及性

頁面使用單一 `h1`；分類使用 `h2`，課程名稱依結構使用 `h3`，清單使用語意化 `ul`／`li` 或等價結構。桌面可並欄呈現分類或課程，手機必須維持「分類說明 → 該分類課程」的單欄閱讀順序。320px 起不得水平溢位；文字放大至 200% 仍可閱讀與操作。所有連結可使用鍵盤到達，焦點樣式可見，點擊區至少 48 × 48px。圖片須提供尺寸以避免版面位移，資訊性圖片使用內容編輯者撰寫的替代文字。

## 驗收條件

1. `/courses` 只有一個 `h1`，並依固定順序呈現四個分類。
2. 僅已發布課程出現；六門已確認課程均歸入正確分類，授課形式與 `PRODUCT.md` 一致。
3. 每個課程連結以 slug 產生 `/courses/[slug]`，元件及 CMS 不含硬編碼完整詳情路徑。
4. 無資料、單分類無課程、讀取失敗、缺圖、100 字摘要及 12 門課程情境都有可觀察結果，且不顯示首頁示範資料。
5. 以 320、390、768、1024、1440px 與 200% 文字縮放檢查：內容無裁切、重疊或水平捲動。
6. 僅用鍵盤可依閱讀順序走訪所有課程連結與重試操作；焦點可見，圖片替代文字符合契約。
7. 多階段梯次可保存並依序顯示所有 date range；跨月、跨年及單日日期皆不需使用自由文字。
8. `run.firstStartDate` 與 `run.lastEndDate` 可由巢狀日期一致推導；日期倒置、重疊或順序重複時不得發布。

## 待決事項與依賴

- 詳情頁最終網址與移除 `/courses` 前綴時的重新導向策略待確認。
- 正式頁面導言、分類摘要、課程摘要、圖片與替代文字待內容團隊提供。
- 課程詳情規格、Sanity 課程與分類 schema、公開查詢及集中式路由 helper 是後續實作依賴。
- 正式報名表單、匯款及付款確認流程不阻擋總覽設計，但會影響詳情頁規格。
- 各階段是否可獨立報名須在建立正式梯次前確認；此決定會影響 stage 與 run 的切分。
